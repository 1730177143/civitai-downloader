# CivitAI / HuggingFace 模型下载器

一个带图形界面的模型下载器，专门解决 **"下载一小点就断开"** 的问题。
多任务队列 · 世界级断点续传 · 分片并行 · 全局限速 · SHA256 校验 · 付费护栏。

支持 **CivitAI**（含付费模型护栏）和 **HuggingFace**（含 hf-mirror 等镜像）。

## 为什么用它

CivitAI 的下载地址是 **307 跳转到 R2 签名地址**，签名几分钟就过期；普通浏览器/`curl` 单连接下载，一断就得从头再来，大文件基本下不完。这个工具做了四件事把它解决掉：

1. **分片并行**：把一个文件切成 N 段，每条连接只负责自己那段。断了只丢当前那一小片，不影响别的段。
2. **真断点续传**：进度落盘到 `<文件名>.part.json`，进程被杀、断网、重启电脑都能接着下。
3. **自动换票**：签名过期（400/401/403）自动重新换取新地址，无限重试 + 指数退避。
4. **下完必校验**：分片完整性 → 文件大小 → safetensors 头 → SHA256，任何一步不过都不会把文件交给 ComfyUI。

## 两种来源

同一个队列、同一套续传和校验，**链接贴进来自动识别**：

| 来源 | 链接形态 | 说明 |
|---|---|---|
| **CivitAI** | `https://civitai.red/api/download/models/<版本ID>?fileId=<文件ID>`<br>或模型页 `…/models/<模型ID>/slug?modelVersionId=<版本ID>` | 需要 API Key；付费模型有护栏（见下） |
| **HuggingFace** | `https://huggingface.co/<仓库>/resolve/main/<文件路径>` | **不需要 CivitAI Key**；`/blob/` 链接也认 |
| **HF 镜像** | `https://hf-mirror.com/<仓库>/resolve/main/<文件路径>` | 路径不变，只换域名；中途切换镜像仍可续传 |

### HuggingFace 的几个细节

- **镜像**：界面「HF 镜像」下拉框，可选官方 / `hf-mirror.com` / 自定义。URL 每次使用前现拼，所以换镜像不用重下。
- **gated 仓库**（要登录并同意条款，例如 `black-forest-labs/FLUX.2-klein-9b-fp8`）：下载会收到 401/403 → **自动弹窗**：显示仓库名 → 打开仓库页面点 Agree → 粘贴 HF Token → 自动重试。
- **校验**：用 HF 的 **LFS 摘要（`lfs.oid`，即 sha256）** 当权威值；非 LFS 小文件没有摘要就跳过校验并记日志。
- **不会自动分类目录**：HF 文件没有"底模/类型"元数据，保存位置要自己选。

## 图形界面说明

### ① 添加下载任务

| 控件 | 作用 |
|---|---|
| 下载地址 | CivitAI API/模型页地址，或 HF `resolve` 直链 |
| 解析 | 取元数据：模型名、底模、类型、文件列表 |
| 选择文件 | 一个版本可能有多个文件/精度，在这里选 |
| 模型根目录 | 你的 `ComfyUI/models` |
| 保存位置 | 相对模型根目录的子目录，可下拉选已有目录 |
| 按基模分目录 | 自动套 `<类别>/<基模>`（如 `loras/Krea2`、`diffusion_models/Anima`），依据是磁盘上已有的目录名 |
| 文件名 | 默认取服务端文件名，可改 |
| 本任务分片数 | 1–32，链不稳就开多几个 |
| 加入后立即开始 | 关掉则只入队不下载 |

### ② 任务队列

| 按钮 | 作用 |
|---|---|
| **▶ 开始/继续** | 排队 / 继续 / 重新开始（保留 `.part` 会续传） |
| **⏸ 暂停** | 暂停但保留连接。**不占并发名额**，队列里的任务会自动补位 |
| **⏹ 停止** | 断开连接、保存进度 |
| **精确重试** | 出错后重新尝试 |
| **清空重下** | 删掉本地残留（`.part` / `.part.json` / `.bad`）后从 0 重下。校验失败就用它 |
| **移除** | 从队列删掉（磁盘 `.part` 保留） |
| **📂 打开文件夹** | 打开该任务的保存目录 |
| **全部停止** | 一键停掉所有任务 |

队列会持久化：关掉界面再打开，历史任务还在（显示为「已停止」，进度从 `.part.json` 读回），点「开始/继续」即可续传，不会自动开跑。

设置行：

- **同时下载 N 个任务**：并发上限（1–8），超出自动排队，完成自动补位；暂停的不占名额
- **全局限速 X MB/s**：所有任务、所有连接**共享**这一个上限；0 = 不限
- **改所选任务的分片数**：按真实已完成区间重切，**只把缺口切给新连接**，进度不归零
- **HF 镜像 / HF Token**：见上文

## 校验机制

下完后按顺序检查，**任何一步不过都不会改名为正式文件**：

| 步骤 | 检查什么 | 不通过时 |
|---|---|---|
| 1. 分片完整性 | 每个分片是否真的写到了区间末尾（`.part` 是预分配成总大小的，**光看文件大小没用**） | 自动补跑没下完的分片；补不齐就报"下载不完整"，**不做 hash 校验**（避免误判） |
| 2. 文件大小 | `.part` 实际长度 == 服务端声明的总长 | 保留 `.part`，可续传 |
| 3. safetensors 头 | 前 8 字节的头长度是否合理 | 仅告警 |
| 4. SHA256 | 全文件 SHA256 == 来源标注值（CivitAI `hashes.SHA256` / HF `lfs.oid`） | 改名为 `.bad`，弹窗问是否「清空重下」 |

### 校验失败怎么办

`.bad` 已经没有复用价值，**直接「清空重下」**最快。常见成因：

| 成因 | 判断 | 处理 |
|---|---|---|
| 下载途中源文件被替换 | 无全零，但 hash 与标注不符 | 清空重下 |
| 来源分发的文件与它标注的 hash 本就不同 | 无全零，重下多次仍失败 | 只能接受，或找发布者确认 |
| 历史版本的"改分片数"缺陷（已修） | `.bad` 里出现大段**全零** | 升级后重下 |

> **旧版本留下的 `.part` 不要续传**：进度记录里可能已经含空洞，新代码无法分辨。这类任务请点「清空重下」。只有 `.part` 没有 `.part.json` 的孤儿残片可直接删。

## 付费护栏

CivitAI 有付费模型，误点会产生真实费用。这里的做法：

1. **元数据级拦截**：解析时 `paidAccess` / `licensingFee` / `usageControl` 命中就标记「付费」
2. **加入队列前二次确认**：必须勾选"我确认会产生费用"才允许加入
3. **HTTP 402 立即停**：下载中遇到 402（付费/余额不足）**立刻停止且绝不重试**，避免反复触发扣费
4. **API 不返回金额**：v1 接口只有付费标记没有价格，所以提供「到 CivitAI 核对价格」按钮，价格以站内页面为准

## 断点续传原理

```
文件:  model.safetensors
        ├── .part        预分配成总大小的数据文件
        ├── .part.json   分片进度 {total, segments:[{start,end,next}], base_done}
        └── .lock        跨进程互斥（防止两个进程同时写坏同一个 .part）
```

- 每条连接只管 `[start, end]`，把 `next` 写回状态文件
- 存进度前先 `fsync` 数据文件，保证状态**永不领先于磁盘**
- `.part.json` 记录文件的 `st_ctime`：`.part` 被重建过就拒绝复用旧进度
- 改分片数时按**真实已完成区间**求补集，只把缺口切给新连接

## 常见问题

**Q：还是下一小点就停？**
A：把分片数调到 12–16，并适当降低全局限速（比如 2 MB/s）。分片越多，单条连接断掉损失越小。

**Q：能在 ComfyUI 里同时下载吗？**
A：可以，`models/` 下新文件会被 ComfyUI 自动识别，不需要重启。

**Q：下载一半想改分片数？**
A：直接在「改所选任务的分片数」里改并点「应用」，会按真实缺口重切，进度不丢。

**Q：为什么有时候下完却提示 SHA256 不符？**
A：先看 `.bad` 里有没有大段全零（说明是没下完被误判完成，属历史缺陷已修）。没有全零就说明来源的文件和它标注的 hash 本身不一致，只能重下或接受。

**Q：CivitAI Key 泄露了怎么办？**
A：立刻到 CivitAI → Account Settings → API Keys 吊销重建。本仓库不会提交任何凭据。
